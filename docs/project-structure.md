# Project Structure

## Purpose and scope

This document is the repository layout reference for `liq-integrations-issues-github`: what each significant directory is for and what the key root-level files do, so a contributor or agent can orient without exploring the whole tree. Build, test, and contribution conventions live in `AGENTS.md` (not yet present in this repository; see [Related documents](#related-documents)) rather than here.

## Directory tree

```text
liq-integrations-issues-github/
├── src/                                    # Provider hook implementations — the package's entire runtime surface
│   ├── index.js                            # setup() — registers the `tickets` and `pull request` provider hooks
│   ├── uses-github-issues.mjs              # Shared activation test (bugs.url must be a github.com URL)
│   ├── create-or-update-pull-request.mjs   # createOrUpdatePullRequest hook
│   ├── get-current-integration-user.mjs    # getCurrentIntegrationUser hook
│   ├── get-issue-url.mjs                   # getIssueURL hook
│   ├── get-project-url.mjs                 # getProjectURL hook
│   ├── get-pull-request-urls-by-head.mjs   # getPullRequestURLsByHead hook
│   ├── get-qa-link-file-index.mjs          # getQALinkFileIndex hook
│   ├── constants.mjs                       # Shared constants
│   └── test/                               # Jest unit tests, co-located with source
├── docs/                                   # Project documentation
│   ├── liq-integrations-issues-github-spec.md  # Canonical functional specification
│   └── project-structure.md                # This document
├── plan/                                   # Active Flow implementation-plan tracking
│   └── manifest.yaml                       # Plan registry manifest
├── dist/                                   # Build output  (generated — not committed content)
├── qa/                                     # QA gate pass markers  (generated by `make qa`; gitignored)
├── test-staging/                           # Transpiled test build output  (generated; gitignored)
├── node_modules/                           # Installed dependencies  (omitted — generated)
└── worktrees/                              # Flow-managed git worktree(s) for active plan work  (untracked session state)
```

## src/

`src/` is the entire runtime surface of the plugin. `index.js` exports the `setup` function that registers two provider entries — `tickets` and `pull request` — with the host `plugable-express` server's `IntegrationsManager`; each of the other top-level `.mjs` files implements one hook named in that registration (PR create/update, issue/project/PR-search URL construction, current-user lookup, QA link-file index) or the shared `usesGitHubIssues` activation test. `constants.mjs` holds values shared across those hooks. `src/test/` holds the Jest unit tests, co-located with the source they exercise rather than segregated into a top-level `test/` directory. The full hook contract — signatures, return types, and behavior — is documented in the [project specification](./liq-integrations-issues-github-spec.md#api-definition), not restated here.

## docs/

`docs/` holds this project's Markdown documentation: the [specification](./liq-integrations-issues-github-spec.md), the canonical statement of what the plugin is required to do, and this project-structure reference. Build/test/contribution conventions, when written, will live in a root-level `AGENTS.md` rather than under `docs/`.

## plan/

`plan/` carries Flow's active implementation-plan tracking for this repository. On the working branch it holds `manifest.yaml`, the plan registry; full plan documents (overview, `TODO.yaml`, task docs) for an in-progress plan live in an isolated plan worktree rather than directly under this directory. This directory reflects Flow's own plan-tracking mechanism, not a project-specific concept.

## Key root-level files

| File | Role |
|------|------|
| `Makefile` | Build/lint/test/qa entry points, built on the `@liquid-labs/catalyst-scripts-node-project` shared build system. |
| `package.json` | npm package manifest; `scripts` delegate to the corresponding `Makefile` targets. Declares the runtime dependencies on the `liq`/`liquid-labs` toolkit libraries the plugin's hooks depend on. |
| `package-lock.json` | Locked dependency graph for reproducible installs. |
| `.gitignore` | Excludes generated build/test/QA output (`dist/`, `qa/`, `test-staging/`, `node_modules/`) and select `.flow/` cache paths from version control. |
