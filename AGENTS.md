# @liquid-labs/liq-controls

Working notes for developers and AI agents contributing to `@liquid-labs/liq-controls`, a plugin for a `@liquid-labs/plugable-express` server that enables and manages policy controls for the orgs the server hosts. This plugin covers control **definition** (loading `*.qcontrols.yaml` files per organization), **storage/retrieval** (an `ItemManager` keyed by normalized control id), and **exposure** (HTTP list endpoints, the `getQuestionControls` integration hook) — it does not implement evaluation, enforcement, or audit-trail logic; that is a consumer's responsibility. Keep that boundary in mind when extending this codebase: walking a control's `actions`, collecting answers, or scoring outcomes belongs in a consuming plugin, not here.

## Build and test

Node.js 18+ and npm (`package-lock.json` is the tracked lockfile). Install dependencies, then use the `make`-driven build/test/lint pipeline (the shared `@liquid-labs/catalyst-scripts-node-project` toolchain, wired through the equivalent `npm run` scripts):

```bash
npm install

make build      # or: npm run build — rollup-bundles src/lib into dist/liq-controls.js
make test       # or: npm test — babel-compiles src into test-staging/, then runs jest (--runInBand)
make lint       # or: npm run lint — eslint, no writes
make lint-fix   # or: npm run lint:fix — eslint --fix
make qa         # or: npm run qa — test + lint together
```

Build, test, and lint configuration (babel, jest, eslint, rollup) is not local to this repo — it is resolved from the installed `@liquid-labs/catalyst-scripts-node-project` package via the `Makefile`'s `INSTALL_BASE` lookup. There is no local `eslint.config.*`, `jest.config.*`, or `babel.config.*` to edit directly.

## Run

`liq-controls` has no standalone run form — it is not a CLI or server in its own right. It is loaded as a plugin dependency by a host `@liquid-labs/plugable-express` server (declared dependencies: `@liquid-labs/liq-projects`, `@liquid-labs/liq-orgs`, per `plugable-express.yaml`), and only runs in that context. To exercise it locally, load it into a host plugable-express server per the [README's installation instructions](./README.md#installation) and hit its HTTP endpoints there.

## Code organization

- `src/lib/setup.mjs` — the plugin's setup-pipeline registrations (`load org controls`, `load controls integrations`).
- `src/lib/resources/` — the control domain model: `controls.mjs` / `control.mjs` / `question-control.mjs` (the `ItemManager`/`Item` classes for loaded control sets) and `load-controls.mjs` (scans and parses `*.qcontrols.yaml` files).
- `src/lib/handlers/` — HTTP handlers, notably `orgs/controls/` (`list.mjs`, `list-implied.mjs`, and the shared `_lib/list-lib.mjs` formatting code path).
- `src/lib/integrations/` — the `getQuestionControls` integration hook and its registration (`register-controls-integrations.mjs`).
- `src/schema/audit.schema.json` — the structural reference schema for `*.qcontrols.yaml` files (published as `dist/audit.schema.json`; not enforced at load time — see the [spec's Non-goals](./docs/liq-controls-spec.md#non-goals)).
- `dist/` — build output (generated by `make build`; not edited directly).
- Tests live alongside the code they cover, under `test/` directories (e.g. `src/lib/resources/test/`, `src/lib/handlers/orgs/controls/test/`), including fixture data under nested `test/data*/` trees.

A fuller repository layout reference is planned at [`docs/project-structure.md`](./docs/project-structure.md).

## Conventions

- Source is a mix of `.js` and `.mjs` (ES module syntax); match the existing file's style when editing.
- Lint and formatting rules come from the shared `@liquid-labs/catalyst-scripts-node-project` eslint config — do not add a local eslint config to override it. Run `make lint-fix` before committing.
- Jest test files are compiled through babel into `test-staging/` before running; edit sources under `src/`, never `test-staging/` directly (`make test` regenerates it).

## External services and dependencies

`liq-controls` does not function standalone. It requires a host `@liquid-labs/plugable-express` server with `@liquid-labs/liq-orgs` and `@liquid-labs/liq-projects` loaded as sibling plugins (declared in `plugable-express.yaml`); the host's plugin loader resolves and loads them. `liq-orgs` supplies organization data and `liq-projects` supplies project/playground resolution — `liq-controls` relies on both rather than resolving organizations or projects itself.
