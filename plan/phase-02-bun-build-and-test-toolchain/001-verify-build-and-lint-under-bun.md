# Verify Build And Lint Under Bun

## Purpose and scope

Prove, in the real repository, that the Catalyst build and lint toolchain works correctly against a Bun-installed `node_modules` — and record that no change is required, so the determination is durable rather than folklore.

The [compatibility research](../notes/catalyst-bun-compatibility.md) already established this with full real invocations, but against a **scratch copy** with illustrative pins and a pre-populated `dist/`. This task retires the residual risk that the actual repository, with task 001's real pin set and a genuinely empty `dist/`, behaves differently.

This is a verification-and-record task. Its success condition includes **modifying no `make/*.mk` file**. Scope excludes the unit-test tier (task 002 owns it), the integration tiers (phase 3), and documentation (phase 4).

No standard skill covers this; follow the procedure below.

## Requirements

1. **Establish a genuinely clean starting state.** `rm -rf node_modules dist qa test-staging`, then provision `.yalc/` and run `bun install`. Record the package count Bun reports. Do not let a stale `node_modules` from an npm install stand in for a Bun-installed tree — the whole point of this task is the provenance of that directory.

2. **Verify config-path resolution.** Confirm each `make/10-resources.mk` lookup resolves against the Bun-installed tree:
   - `npm explore @liquid-labs/catalyst-resource-babel-and-rollup -- pwd` (used for both `CATALYST_BABEL_CONFIG` and `CATALYST_ROLLUP_CONFIG`)
   - `npm explore @liquid-labs/catalyst-resource-eslint -- pwd`
   - `npm explore @liquid-labs/catalyst-resource-jest -- pwd`

   Confirm the file each variable actually points at exists on disk — a resolving directory with a missing `dist/babel/babel.config.cjs` would pass a naive check and fail the build.

   Also confirm the `node_modules` shape the research predicted: those package directories are real directories rather than symlinks into a global Bun cache, and `node_modules/.bin/*` entries are ordinary relative symlinks (`babel -> ../@babel/cli/bin/babel.js`).

3. **Run `make build` and verify both artifacts.** `dist/sdlcforge-server.js` (from `src/lib/index.js`) and `dist/sdlcforge-server-exec.js` (from `src/cli/index.js`) must both be produced, each a 12-line externals-only bundle whose dependency references are bare `require()` calls, each with a `.js.map` sibling, and the executable carrying `#!/usr/bin/env -S node --enable-source-maps` and the executable bit. (Corrected from the originally-planned 9 lines: the `catalyst-bun-compatibility.md` research spike's 9-line figure predates phase 1 task 004's XDG `serverConfigRoot`/`seedServerSettings` change, which legitimately added functional code to `src/lib/app-init.mjs` — verified by task 2/001's own dispatch to still be externals-only in substance, `grep -c shelljs` returning 0.)

4. **Run `make lint` and `make qa`.** `make lint` must run ESLint to completion and write `qa/lint.txt`. It reports pre-existing style violations; that is known lint debt, not a Bun regression, and its presence is the expected baseline. `make qa` chains `test` and `lint`.

5. **Record the determinations** in the task report, for phase 4 to consume:
   - No `make/*.mk` file needed modification, and none was modified. These files are generated by `@liquid-labs/catalyst-lib-makefiles` and `@liquid-labs/catalyst-builder-node`; a hand-edit would be lost on regeneration, so "no change needed" is a positive outcome rather than a deferral.
   - `npx` was not converted to `bunx`. Both work; the change is optional and would touch generated files.
   - **Node and the `npm` binary remain toolchain prerequisites.** Every Catalyst tool is a Node-targeted CLI with a `#!/usr/bin/env node` shebang, and `npm explore` needs the npm binary on `PATH`. Report the observed Node, npm, and Bun versions. The verified fallback, should npm ever have to leave the toolchain, is `require.resolve('<pkg>/package.json')` with the trailing `/package.json` stripped, which produces byte-identical output to `npm explore … -- pwd`; record it as the documented escape hatch, but do **not** implement it.

6. **If any step fails**, do not begin editing generated makefiles on your own initiative. Halt and report the specific failure, with the command and its output — a divergence from the research finding is a planning-level event, not something to patch around inside this task.

## Validation

- `git status` shows no modification to any file under `make/`, and `git diff --stat` for the task is empty apart from any plan/task-doc updates.
- `bun install` from clean exits 0 with no `failed to resolve` output.
- Each of the three `npm explore … -- pwd` invocations exits 0 and prints a path under this repository's `node_modules/`; the four `CATALYST_*_CONFIG` files those paths imply all exist.
- `make build` exits 0. `wc -l dist/sdlcforge-server.js dist/sdlcforge-server-exec.js` reports 12 lines each (see Requirement 3's note on why this figure was corrected from 9); `head -1 dist/sdlcforge-server-exec.js` is the `node` shebang; `test -x dist/sdlcforge-server-exec.js` passes; `dist/sdlcforge-server.js.map` and `dist/sdlcforge-server-exec.js.map` exist.
- `grep -c shelljs dist/sdlcforge-server-exec.js` returns `0` — the bundle is still externals-only.
- `make lint` runs to completion and `qa/lint.txt` exists and begins with a `Test git rev:` line.
- `make qa` exits according to its constituent targets, with no error attributable to tool resolution.
- Observed Bun, Node, and npm versions are captured in the report.

## Assumptions

- Phase 1 has landed in full: `package.json` carries no wildcard specifier, `bun.lock` is committed, `package-lock.json` is gone, and `src/lib/app-init.mjs` resolves its config root through comply-defaults.
- This task's worktree needs `.yalc/` provisioned before `bun install` — use `scripts/provision-local-deps.sh` from phase 1 task 002.
- `make lint` reporting pre-existing violations is expected. Do not "fix" them; that is out of scope and would obscure the signal this task exists to produce.
- `dist/` and `qa/` are gitignored, so nothing this task builds shows up in `git status`.
