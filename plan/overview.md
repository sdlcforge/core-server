# Bun Conversion

## Purpose and scope

Convert `@sdlcforge/core-server` from npm to Bun for **package management**, following the pattern already proven in the sibling project `sdlcpilot-cli`, and adopt an XDG-compliant server configuration root along the way.

This plan covers core-server's own conversion only. It is item 3 of a larger modernization backlog; the full seven-phase modernization synthesis is background context, not scope.

### What must change

- `bun install` and `bun.lock` replace `npm install` and `package-lock.json`.
- Wildcard (`*`) dependency specifiers become explicit semver ranges. This is not cleanup — it is a hard prerequisite, established below.
- A repeatable procedure must exist for provisioning the gitignored `file:.yalc/…` dependencies into a task worktree, and the CI and Docker positions must be recorded explicitly rather than left implicit.
- `serverConfigRoot` moves from the package-relative `myPackagePath` to `${XDG_DATA_HOME}/sdlcforge-core/`, resolved through a new `@liquid-labs/comply-defaults` accessor.
- The Catalyst makefile toolchain must be *verified* to resolve and run correctly against a Bun-installed `node_modules`.
- All three test tiers must pass.
- `README.md`, `AGENTS.md`, `CLAUDE.md`, `docs/architecture.md`, `docs/core-server-spec.md`, and `docs/project-structure.md` must stop describing an npm-managed project with a package-relative config root.

### What must not change

- **The runtime contract.** `dist/sdlcforge-server-exec.js` keeps `#!/usr/bin/env -S node --enable-source-maps`, `engines.node` stays `>=18.0.0`, and the Docker Node 18–24 matrix stays the meaningful compatibility contract. Bun is a *development* dependency of this project, never an install-time requirement for consumers. The [runtime-target decision](./notes/runtime-target-decision.md) records this and defers a bun-if-available launcher to a followup outside this plan.
- **The dual build-artifact contract.** `dist/sdlcforge-server.js` (library, from `src/lib/index.js`) and `dist/sdlcforge-server-exec.js` (executable, from `src/cli/index.js`) both survive, with the same entry points and the same externals-only shape.
- **The Makefile/Catalyst build convention.** Rollup and Babel stay, and `make/*.mk` is not hand-edited at all — the [compatibility research](./notes/catalyst-bun-compatibility.md) found no change is required, and these files are generated by `@liquid-labs/catalyst-lib-makefiles` / `@liquid-labs/catalyst-builder-node`, so a hand-edit would be lost on regeneration.
- **The three-tier test structure**, and the unit tier's runner. Jest continues to run under Node against a Bun-installed `node_modules`. A `bun test` migration is technically viable but is explicitly **out of scope** — the rationale is recorded below.
- **The server's HTTP API surface.** The golden-api-spec characterization test (`src/lib/test/golden-api-spec.test.js` plus `test/__snapshots__/`) is the regression harness for this and must keep passing unmodified.
- **The plugin architecture.** Three tiers, 13 explicit plugins, runtime discovery and dynamic install, all unchanged.

### Success criteria

1. `bun install` succeeds from a clean checkout (given the documented `.yalc/` provisioning step) and produces a working `node_modules`.
2. `make build` produces both `dist/` artifacts with unchanged entry points, unchanged externals-only output, and the unchanged `node` shebang.
3. `make test`, `bun run test:local`, and `bun run test:integration` all pass, including the golden-api-spec snapshots byte-for-byte.
4. `make lint` and `make qa` pass.
5. `package-lock.json` is gone; `bun.lock` is committed.
6. No `*` version specifier remains in `package.json`.
7. The server resolves its configuration root to `${XDG_DATA_HOME}/sdlcforge-core/` (defaulting `XDG_DATA_HOME` to `${HOME}/.local/share`), guarded against an undefined `HOME`, through `@liquid-labs/comply-defaults`.
8. Documentation matches reality.

### Pre-conditions every task dispatch must satisfy

`.yalc/` and `yalc.lock` are gitignored, so **a freshly created task worktree has no `.yalc/` directory at all**, and `bun install` (including the `--frozen-lockfile` form `create-worktree.sh` uses when a lockfile is present) fails hard on the two `file:.yalc/…` dependencies. Every task worktree in this plan must therefore be provisioned as:

```bash
create-worktree.sh --no-install-deps …          # suppress automatic install
cp -R "$PROJECT_ROOT/.yalc" "$WORKTREE_PATH/.yalc"
(cd "$WORKTREE_PATH" && bun install)
```

Phase 1 turns this into a checked-in script, but the manager must apply it by hand for Phase 1's own dispatches. The [yalc-provisioning research](./notes/bun-yalc-provisioning.md) has the full evidence.

### Findings that shape the plan

**The WIP branch is stale, not contaminated.** `work-sdlcforge/core-server/64` branched from `dd775e0`, 45 commits behind current `main`. It is a read-only reference — not merged, rebased, or cherry-picked. Its one durable contribution is the dependency-pinning *intent*; its pin list itself carries an `^1.0.0-alpah.2` typo and must be re-derived, never transcribed. Its five added dependencies (`git-toolkit`, `github-toolkit`, `npm-toolkit`, `playground-monitor`, `sdlc-lib-build`) are [dropped outright](./notes/added-dependencies-decision.md).

**`bun install` currently fails outright.** Against `main`'s `package.json` it errors on all **12** wildcard dependencies (the earlier count of 11 was low by one):

```
error: No version matching "*" found for specifier "@liquid-labs/liq-controls" (but package exists)
```

Every one of these packages publishes only `1.0.0-alpha.N` prereleases, and a bare `*` does not match a prerelease under strict semver. npm tolerates this; Bun does not. Pinning is therefore the first blocking task, not a tidiness pass.

**The Catalyst toolchain needs no changes at all.** The research spike confirmed, with full real build/test/lint runs against a Bun-installed `node_modules`, that `npm explore … -- pwd` config resolution, `npx babel/rollup/jest/eslint` invocation, and the Jest unit suite all work unmodified. Phase 2 therefore reduces from "repoint the makefiles off npm" to "verify, in the real repository, that no repointing is needed" — a materially smaller phase than originally scoped. One consequence must be stated rather than glossed: **Node and the `npm` binary remain toolchain prerequisites** (every Catalyst tool is a Node-targeted CLI with a `#!/usr/bin/env node` shebang, and `npm explore` needs the npm binary on `PATH`). "Bun conversion" here means Bun *installs the dependency tree*; it does not mean npm disappears from the developer toolchain.

**Bun caches a `file:` dependency's transitive graph in `bun.lock` and will not refresh it.** A bare `bun install` — and `--force`, `--no-cache`, and a version bump — all fail, silently and with a success message, to pick up a new transitive dependency of a yalc-pushed package. Only `rm -f bun.lock && bun install` re-resolves it. `AGENTS.md`'s current "run `npm install` after any yalc push" instruction must therefore become a strictly stronger one, not a mechanical `npm`→`bun` substitution.

**Moving `serverConfigRoot` relocates a real file.** `@liquid-labs/plugable-express` reads `<serverConfigRoot>/server-settings.yaml` at init and, when absent, writes an empty `{}` there. This repository ships a `server-settings.yaml` carrying the `registries:` list that drives dynamic plugin lookup, and it currently sits at `myPackagePath` — so it is found today purely because the config root *is* the package root. Moving the config root to `${XDG_DATA_HOME}/sdlcforge-core/` silently drops that setting unless the packaged defaults are seeded into the new location. Phase 1 handles this explicitly; it was not contemplated by the original question or its answer, and is flagged to the manager.

## Overview

Four phases. Phases 1 through 3 are strictly sequential — each leaves the project in a working state and each depends on the previous phase's output. Phase 4 documents the result.

### Phase 1 — Bun package-management baseline

Makes `bun install` work, and makes the dependency tree reproducible somewhere other than the author's machine. Also lands the `serverConfigRoot` change, which is placed here because its first task is cross-repository and carries publish lead time that should start as early as possible.

Tasks:

1. **`001-pin-dependencies-and-adopt-bun-lockfile`** — re-derive an explicit range for each of the 12 wildcard specifiers against currently-published versions, generate `bun.lock`, delete `package-lock.json`.
2. **`002-establish-yalc-provisioning-procedure`** — a checked-in provisioning script plus the corrected post-`yalc push` instruction and the recorded CI policy. Depends on task 001.
3. **`003-add-server-config-root-accessor-to-comply-defaults`** — **executes in the `@liquid-labs/comply-defaults` repository, not this one.** Adds and publishes `COMPLY_SERVER_CONFIG_ROOT()`. Independent of tasks 001 and 002, so parallel-eligible with task 001.
4. **`004-adopt-xdg-server-config-root`** — consumes the new accessor in `app-init.mjs` and preserves the packaged `server-settings.yaml` defaults. Depends on tasks 001 and 003.

The build and test toolchain is deliberately left alone here, which keeps the phase's blast radius on dependency resolution and yields a clean before/after signal.

**Exit state:** `bun install` succeeds; `make build`, `make test`, and `make lint` still pass; the server resolves its config root through comply-defaults.

### Phase 2 — Build and test toolchain verification

Confirms, in the real repository rather than the spike's scratch copy, that the Catalyst toolchain works against the Bun-installed tree — and records the "no changes required" determination so it is not re-litigated. The spike used illustrative pins, a scratch copy, and a pre-populated `dist/`; this phase retires the residual risk that the real repository behaves differently.

Tasks, both parallel-eligible:

1. **`001-verify-build-and-lint-under-bun`** — `make build`, `make lint`, `make qa`, and artifact-shape verification.
2. **`002-verify-unit-test-tier`** — `make test`, golden snapshots byte-for-byte, coverage into `qa/coverage/`, and the written record of the Jest-stays decision.

**Exit state:** `make build`, `make test`, `make lint`, and `make qa` all pass against a `bun install`-produced `node_modules`, with evidence captured and no `make/*.mk` file modified.

### Phase 3 — Runtime confirmation and integration tiers

Brings the two integration tiers and the operational scripts into line. The runtime decision is a no-change, so this phase *confirms* the shebang and `engines` rather than altering them, and converts the npm invocations that surround them.

Tasks, both parallel-eligible:

1. **`001-convert-local-integration-tier`** — `scripts/test.sh` and `scripts/start.sh`; `bun run test:local` passing against the new config root.
2. **`002-convert-docker-integration-tier`** — `test/run-integration-tests.sh`, the bind-mount architecture confirmation, `test/test-ci.sh`, and deletion of the dead `test/setup-local-deps.sh`.

**Exit state:** all three test tiers pass; `bun run start` / `bun run stop` work; the Node 18–24 matrix is intact.

### Phase 4 — Documentation updates

The conversion changes spec-defined behavior (the configuration root, and the package-management story), the tech stack and build-pipeline descriptions in `docs/architecture.md`, and every build/test/run command in `AGENTS.md`, `CLAUDE.md`, and `README.md`. `docs/project-structure.md` still lists `package-lock.json`.

Tasks, both parallel-eligible:

1. **`001-update-architecture-docs`** — `docs/architecture.md` and `docs/core-server-spec.md`.
2. **`002-update-contributor-and-consumer-docs`** — `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/project-structure.md`.
