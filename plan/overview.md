# Overview

## Purpose and scope

This is the `core-server-domain-consolidation` plan-group of the `sdlcforge-modernization` wave plan (wave: "Plugin Consolidation — Framework and Dev-Core", lead project: `core-server`). It federates four projects under one plan slug — `liq-controls`, `liq-credentials`, `liq-integrations-issues-github` (this project), each a donor originating a relocation of its own plugin source, and `core-server`, the fold-in target that absorbs all three via git-history-preserving merge and retires each donor. The plan-group follows the absorption convention established by two completed sibling plan-groups in the same wave: `dev-core-consolidation` (whose [`docs/dev-core-consolidation-contract.md`](/Users/zane/playground/sdlcforge/dev-core/docs/dev-core-consolidation-contract.md) is the canonical model for the absorption recipe, layout convention, root-file ownership, retirement policy, and publishing hygiene) and `framework-consolidation`. Behavior is preserved throughout; pre-existing defects are documented rather than silently fixed.

### This project's slice (liq-integrations-issues-github)

`@liquid-labs/liq-integrations-issues-github` (currently `1.0.0-alpha.3`) is a `@liquid-labs/plugable-express` plugin that backs the `liq-integrations` hook registry with GitHub's Issues, Pull Requests, Projects, and Milestones APIs. Its complete surface — confirmed from source — is **two integration-provider registrations carrying seven hook registrations, and zero HTTP routes**. It contributes no route, no path variable, and no `app.ext` publication of its own; it only *consumes* `app.ext.credentialsDB` and `app.ext._liqProjects.playgroundMonitor`. That makes it the one donor in this plan-group whose absorption cannot be verified from a route snapshot at all — the provider/hook table is the entire observable contract, which is why `core-server`'s own absorb task pins its verification to a `register()`-call baseline instead.

Structurally it matches the sibling `liq-credentials` donor rather than `liq-controls`: **its source roots directly at `src/`, not `src/lib/`**. The relocation is a `git mv` of everything under `src/` into `src/integrations-issues-github/`, with the root `src/index.js` reduced to a thin re-export — kept, not deleted, so the package stays independently buildable and publishable through the interim. `core-server`'s own absorb task `git rm`s that file after merging; it must exist as a thin re-export at merge time.

This project's slice carries one piece of scope the other two donors do not, and it is the highest-priority item in this plan: **inlining `determineCurrentMilestone`**. `src/create-or-update-pull-request.mjs` imports that function from `@liquid-labs/liq-projects-lib`, and this import is the last thing standing between the otherwise-finished `dev-core-consolidation` plan-group and its closeout — that plan-group's final remaining task is `liq-projects-lib`'s own phase 10 task 003 (npm deprecate), which cannot safely run while a live package still depends on it. Copying the function's implementation into this repository and dropping the dependency unblocks that closeout. It is valuable entirely on its own, independent of the rest of this fold, so it is this plan's **first phase — standalone, ungated, and mergeable to `main` the moment it is green**, not bundled into or blocked by the relocate/retire work.

Full findings — file census, provider/hook table, dependency inventory, the `determineCurrentMilestone` analysis, consumer inventory, build wiring, and the eight recorded anomalies — are in the [source inventory](./notes/liq-integrations-issues-github-source-inventory.md).

## Overview

Three phases. Phase 12 is independent of everything; Phases 13 and 14 are strictly sequential after it.

### Phase 12 — Inline Determine Current Milestone

Removes this repository's dependence on `@liquid-labs/liq-projects-lib` by copying `determineCurrentMilestone`'s implementation into this repository's own source, so `liq-projects-lib` can be deprecated. Standalone: no gate, no dependency on any other phase of this plan, dispatchable and mergeable to `main` immediately. Two tasks, sequential:

1. **`001-inline-determine-current-milestone.md`** (tier `sonnet-high`) — create `src/determine-current-milestone.mjs` carrying the function verbatim, repoint `create-or-update-pull-request.mjs`'s import to it, drop `@liquid-labs/liq-projects-lib` from `dependencies` while adding `@liquid-labs/versioning` and `@liquid-labs/octocache`, and verify `make build`/`make test`/`make lint` green with PR milestone-assignment behavior unchanged. Landing this task alone is what unblocks `liq-projects-lib`'s deprecation.
2. **`002-correct-docs-external-dependency-claims.md`** (tier `sonnet-med`) — corrects the four specific places across `docs/liq-integrations-issues-github-spec.md`, `AGENTS.md`, and `docs/project-structure.md` that describe the `liq-projects-lib` import as a live, unresolved external dependency. Scoped to that factual correction; not general doc authoring.

### Phase 13 — Relocate Plugin Source

Relocates the entire `src/` tree in place to `src/integrations-issues-github/…`, the shape `core-server`'s `git merge --allow-unrelated-histories` absorption will preserve, and keeps the package independently green throughout. One task:

1. **`001-restructure-src-into-core-server-layout.md`** (tier `sonnet-high`) — `git mv` everything under `src/` into `src/integrations-issues-github/` preserving internal structure exactly, replace `src/index.js` with `export * from './integrations-issues-github'`, and verify the provider/hook surface, setup-method name and deps, build, test, and lint at the pre-move baseline. No `Makefile` change is expected.

### Phase 14 — Retire Liq-Integrations-Issues-Github

Implements `dev-core-consolidation-contract.md`'s [source-package retirement policy](/Users/zane/playground/sdlcforge/dev-core/docs/dev-core-consolidation-contract.md#source-package-retirement-policy): verify the absorption first, then documentation and metadata, then the publish attempt. No code deletion, and no re-export shim left registered as a live plugin — the Phase 13 build-entry-point re-export is not one, and is required. Four tasks, task 1 gating the rest:

1. **`001-verify-core-server-absorption.md`** (tier `sonnet-med`) — read-only gate: confirms `core-server` actually carries this donor's complete relocated tree with history preserved, both provider registrations present exactly once with all seven hooks and the setup method's exact name and deps, the inlined `determineCurrentMilestone` absorbed with `@liquid-labs/versioning` and `@liquid-labs/octocache` declared, `core-server`'s own `package.json` and `explicitPlugins` no longer carrying `@liquid-labs/liq-integrations-issues-github`, and `core-server`'s build/test/lint green. Halts the phase on any gap; edits nothing.
2. **`002-author-readme-superseded-notice.md`** (tier `sonnet-med`) — rewrites the committed `README.md` as the final superseded notice: supersession banner naming `@sdlcforge/core-server`, an accurate zero-routes/two-providers/seven-hooks statement of what the package did, the confirmed single-consumer inventory, the `determineCurrentMilestone` inlining as part of the package's final history, and disclosure of the pre-existing defects recorded in the source inventory.
3. **`003-mark-package-deprecated-and-bump-version.md`** (tier `sonnet-low`) — `package.json` only: deprecation-leading `description` (currently the empty string), version bump `1.0.0-alpha.3` → `1.0.0-alpha.4`, publishing-hygiene check on what `npm pack` actually ships, `make qa` green.
4. **`004-publish-final-and-deprecate-on-npm.md`** (tier `sonnet-low`) — attempts `npm publish` and `npm deprecate`; hands the exact commands to the user verbatim if the environment blocks either. GitHub repository archival is left as an explicit, separate human decision.

**Dependencies.** Phase 12 → Phase 13 → Phase 14. Phase 12's own two tasks are sequential (task 002 corrects docs to describe the state task 001 creates). Phase 13's single task is a straight `git mv` of whatever Phase 12 left. Within Phase 14, task 1 gates tasks 2–4; tasks 2 and 3 are parallel-eligible once task 1 passes (disjoint files: `README.md` vs. `package.json`); task 4 runs last, after both 2 and 3 have landed, so the published tarball carries both. Phase 14 as a whole is additionally gated on `core-server`'s own absorption phase landing — a cross-project ordering constraint this plan cannot enforce through its own tooling, flagged to the dispatching manager.

Phase 12 is only *soft*-ordered ahead of Phase 13: nothing breaks if the relocation lands first, but the inlining would then have to be authored against the relocated paths and the two would churn the same files twice. Its real ordering constraint is the opposite direction and external — it should land as early as possible, because another plan-group is waiting on it.

No `## Metadata` / `architectural_impact` flag applies to any task in this plan. Nothing here changes a public API or component boundary (the two provider registrations, all seven hooks, the setup method's name and `deps`, and every hook signature are explicitly preserved byte-identical), introduces a subsystem, or adds or removes tracked state. The `determineCurrentMilestone` inlining changes *where an implementation lives*, not what the plugin does: the function is copied verbatim, its call site keeps the same arguments, and milestone assignment behaves identically. The specification statements that go stale are documented *constraints* about a dependency, not specified behavior, and Phase 12 task 002 corrects them in-phase — so the architectural implications check registers no `doc-updates` phase.
