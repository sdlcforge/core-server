# Bun Build And Test Toolchain

## Goals

Establish, in the real repository, that the Catalyst build/test/lint toolchain works correctly against a Bun-installed `node_modules` — and record that determination durably so it is not re-litigated.

This phase is materially smaller than originally scoped. The [compatibility research](../notes/catalyst-bun-compatibility.md) ran full, real `make build`, `make test`, and `make lint` invocations against a Bun-installed tree and found that **nothing needs to change**:

- `make/10-resources.mk`'s four `$(shell npm explore @liquid-labs/catalyst-resource-… -- pwd)` config lookups resolve correctly. `npm explore` consults no lockfile and no installation provenance — it walks `node_modules` the way Node's own resolution does, and Bun produces a standard, real (non-symlinked-store) `node_modules` tree.
- `npx babel`, `npx rollup`, `npx jest`, and `npx eslint` all resolve through the ordinary `node_modules/.bin/*` relative symlinks Bun creates. `bunx` works identically but switching is optional.
- The Jest unit suite passes unchanged: 3 suites, 5 tests, coverage generated. Jest runs under **Node**, as it always has; forcing Jest onto the Bun runtime (`bunx --bun jest`) fails structurally in `jest-runtime`'s module sandboxing and must not be pursued.

The phase therefore has two jobs rather than one. The first is **verification**: the spike ran against a scratch copy with illustrative pins and a pre-populated `dist/`, so the residual risk that the real repository behaves differently is real and cheap to retire. The second is **recording the decisions**, so that later readers do not mistake "we did not change the makefiles" for "we did not consider it":

- `make/*.mk` is not hand-edited. Beyond the fact that no edit is needed, these files are generated by `@liquid-labs/catalyst-lib-makefiles` and `@liquid-labs/catalyst-builder-node` and carry a header saying so; a hand-edit would be silently lost on regeneration.
- Jest stays. A `bun test` migration is technically viable — verified working in two modes — but buys no compatibility, and costs mandatory explicit path scoping (bare `bun test` double-discovers `src/lib/test/` and `test-staging/lib/test/` and produces a real cross-contamination failure), a coverage-output change from an Istanbul directory to a single `lcov.info`, and a re-check of the downstream `@liquid-labs/sdlc-projects-badges-coverage` consumer.
- Node and the `npm` binary remain toolchain prerequisites. Every Catalyst tool is a Node-targeted CLI, and `npm explore` needs the npm binary on `PATH`. The originally-stated goal of "no npm on the path" is not achievable without editing generated files, and is not worth chasing. If a future environment ever must drop npm, the verified drop-in is `require.resolve('<pkg>/package.json')`, which produces byte-identical output.

Rollup and Babel stay. The one input that could have reopened that — `npm explore`-based config resolution proving unworkable — did not materialize.

## Inputs

- Phase 1's pinned `package.json`, committed `bun.lock`, and worktree-provisioning script.
- The [Catalyst toolchain compatibility research](../notes/catalyst-bun-compatibility.md).
- The existing `make/*.mk` set, the golden-api-spec snapshots as the regression oracle, and the `qa/coverage/` output contract.

## Outputs

- Recorded evidence that `make build` produces both `dist/` artifacts with unchanged entry points, unchanged externals-only shape, and the unchanged `node` shebang.
- Recorded evidence that `make test` passes with the golden-api-spec snapshots byte-for-byte unmodified and coverage written to `qa/coverage/` in the existing Istanbul directory shape.
- Recorded evidence that `make lint` and `make qa` behave as they did before the conversion.
- A durable statement of the three decisions above, ready for Phase 4 to fold into `AGENTS.md` and `docs/architecture.md`.
- Zero modifications to any `make/*.mk` file — a positive deliverable of this phase, not an omission.
