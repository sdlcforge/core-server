# Pre-Merge Baseline And Drift Clearance

## Purpose and scope

Phase 1 of the `sdlc-core-unification` plan. Establishes what "unchanged" means before anything changes, and clears the one known pre-existing drift so it cannot later be misattributed to the merge.

## Goals

This phase comes first because the absorption's central verification question — "did anything move that should not have?" — is unanswerable after the fact. The predecessor plan-group (`core-server-domain-consolidation`) learned this at three components; at seven, with 112 routes changing provenance in one step, an unrecorded baseline makes Phase 4 a series of judgment calls instead of a checklist.

1. **Fix the pre-existing `@liquid-labs/npm-toolkit` breakage before anything touches the lockfile.** `src/controls/handlers/orgs/controls/list-implied.mjs:3` imports `getPackageOrgAndBasename` from `@liquid-labs/npm-toolkit`, a function that no longer exists: it was renamed to `getPackageOrgBasenameAndVersion` in `1.0.0-alpha.17`, and the installed and locked version is `1.0.0-alpha.21`. This is a **live break on `main` today**, not one this plan creates — `core-server`'s own declared range `^1.0.0-alpha.15` already admits alpha.17+ — and it has stayed invisible only because the handler is reachable only through an `X-CWD` header and no unit test calls it. The [dependency-union research](../notes/dependency-union.md#confirmed-break-getpackageorgandbasename-no-longer-exists) confirmed the missing export by `require()` against `core-server`'s own `node_modules` and bisected the rename against the registry.

   The fix is **two edits, not one**: the replacement is `async`, so `list-implied.mjs:18`'s synchronous destructure (`const { org: orgKey } = getPackageOrgAndBasename({ pkgDir : cwd })`) needs an `await` as well as the new name — without it the destructure silently yields `orgKey === undefined` instead of throwing. The enclosing `func` is already `async`, and the existing `{ pkgDir : cwd }` argument already satisfies the replacement's stricter exactly-one-key contract, so nothing else moves.

   It comes first in this phase because every later dependency operation — this phase's own drift-refresh, and Phase 2's `rm -f bun.lock && bun install` — is what would first surface it as a live crash, and landing it standalone keeps the union commit from appearing to be the commit that broke it.

2. **Clear the yalc drift.** The installed `node_modules/@sdlcforge/dev-core` snapshot lacks `optional: true` on the `orgs` component's `appExt:_liqOrgs.orgSetupMethods` requirement, which `dev-core`'s own `main` HEAD carries (dev-core followup `x6x1`). Refresh the snapshot per this project's documented Bun procedure and re-run the plugin-graph gate. The expected result is that `ALLOWLISTED_ERROR_FINDINGS`' first entry becomes stale immediately — the `unsatisfied` finding downgrades to `info` — leaving exactly one error-severity finding (`violated-by-source-order` on `appExt:_liqOrgs.orgs` for `@sdlcforge/core-server#controls`) *before* any merge. Dropping that first allowlist entry is legitimate work for this phase, not Phase 4's: it is a pre-existing correction, and doing it here keeps Phase 4's own tightening attributable purely to the merge.
3. **Capture a re-runnable baseline** of every observable the merge could move — not a prose description of one. The predecessor's `full-tier-baseline.test.js` harness and its three checked-in snapshots already mechanize most of this; the gap is the non-snapshot observables (setup-method name/`deps` pairs, the `app.ext` key set, the registered path-variable set, the live plugin-graph finding set).
4. **Author this merge's parity contract** — the enumerated, agreed-in-advance list of every baseline observable expected to change, with the reason for each, so that *anything not on the list is a regression*. Modelled directly on [`resources/absorption-parity-contract.md`](../resources/absorption-parity-contract.md), which is the same document written for the same repository one absorption earlier.
5. **Record the pre-merge blob identity of every root-level tracked path.** The recipe's most-repeated warning is that git's conflict list is not the review list, and a recorded blob map turns Phase 2's root-file verification from "did git ask me about it?" into a mechanical comparison.

   The [merge-arrival inventory](../notes/merge-arrival-inventory.md#2-makefile-makemk-gitignore-are-not-byte-identical) has since **re-aimed** what that map is for. The feared hazard — a byte-identical generated build file merging silently — does not exist in this merge: the two repositories sit on different toolchain generations (`CATALYST_*` versus `SDLC_*`), so all nine shared build files conflict loudly and git surfaces every one. Exactly one path in the whole merge merges silently (`plan/manifest.yaml`, byte-identical and therefore a no-op). The real unreviewed-arrival surface is the **clean-add** set — 169 paths, of which 10 need a per-path decision — so the blob map's job is to make *those* mechanically checkable, plus to prove the three paths a careless resolution could clobber (`src/lib/index.js`, `bun.lock`, `.catalyst-data.yaml`) came through untouched. Record the map for every root-level tracked path anyway; it is cheap and it is what makes Phase 2's verification a comparison rather than a recollection.
